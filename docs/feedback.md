# Обратная связь первых пользователей

## Для пользователя

После входа кнопка «Написать отзыв» доступна на любой странице: на компьютере — в верхней панели, на телефоне — значок сообщения рядом с аккаунтом. Выбирается тип «Проблема», «Идея» или «Другое» и вводится сообщение от 10 до 4000 символов. У каждого типа своя подсказка.

По желанию прикладываются название раздела и тип устройства. Флажок можно снять. Параметры ссылки, конкретный номер рецепта, данные цели и меню, снимки экрана и диагностические журналы автоматически не передаются. Текст отзыва виден автору и сотрудникам с доступом к обратной связи.

После отправки показывается номер обращения. В «Моих обращениях» (`/feedback`) сохраняются текст, статус и ответ команды. Статусы: «Получен», «В планах», «В работе», «Готово», «Закрыт». Обновления видны после открытия раздела или нажатия «Обновить». Уведомлений по email, вложений и публичной доски в первой версии нет.

При закрытии заполненной формы можно оставить черновик в текущей вкладке. Он хранится в памяти до перезагрузки или выхода из аккаунта; в localStorage текст не записывается. При ошибке отправки текст остаётся в форме. Повтор той же отправки использует прежний идентификатор и не создаёт дубликат.

## Для команды

Закрытый раздел `/feedback/admin` доступен только аккаунтам с отдельным правом `User.canManageFeedback`. Общая роль `admin` сама по себе доступа не даёт. Право проверяется в базе при каждом запросе; регистрации с привилегиями, разрешения по одному совпадению email или флагов доступа из браузера нет.

«Входящие отзывы» содержат фильтры по типу и статусу, текст, email автора, дату и приложенный контекст. По умолчанию показаны новые обращения. В карточке можно изменить статус и оставить ответ до 2000 символов. Ответ появится у автора в приложении. Одновременные изменения защищены номером версии: если другой сотрудник уже сохранил обращение, интерфейс предлагает загрузить актуальную версию, сохраняя текущий черновик до подтверждения замены.

## Подготовка существующей установки

Сначала сделайте резервную копию базы и соберите новую версию. Перед запуском обновлённого API примените обе добавочные миграции:

- `20261002000000_feedback` — таблица, типы и индексы обратной связи;
- `20261002010000_feedback_access` — отдельное право, по умолчанию выключено у всех.

Команды из корня проекта, на Node.js 24:

```sh
npm run db:backup
npm run db:generate
npm run db:migrate
npm run build
npm run feedback:admin -w @meal-planner/backend -- grant owner@example.com
```

Email замените на уже зарегистрированный и проверенный аккаунт владельца. Команда не создаёт аккаунты и прекращает работу при отсутствии или неоднозначном совпадении. Она меняет только право на отзывы, не затрагивая роль аккаунта. Для отзыва доступа используйте `revoke` вместо `grant`. После выдачи доступа обновите страницу приложения; отзыв права действует сразу на API.

На сервере с Docker Compose после обычного релиза, применения миграций и запуска нового backend:

```sh
docker compose exec -T backend node dist/src/feedback-admin.js grant owner@example.com
```

Команда выполняется в `/opt/meal-planner`, в контексте настроенного серверного Compose. Общая процедура релиза, проверки и откат описаны в [эксплуатации сервера](server-deployment.md). Миграции обратной связи не требуют пересчёта или удаления пользовательских меню. Права в локальной и серверной базах назначаются независимо.

## API и ограничения

Все маршруты требуют действующей сессии.

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /feedback` | Создание: `requestId` UUID, `category`, `message`, необязательные `pagePath` и `deviceType` |
| `GET /feedback` | Только обращения текущего пользователя |
| `GET /feedback/admin` | Обращения команды, фильтры `status` и `category` |
| `GET /feedback/admin/:id` | Актуальная версия для команды |
| `PATCH /feedback/admin/:id` | `status`, `reply`, `version`; конфликт изменений возвращает 409 |

Списки используют курсор `cursor` и `limit` (20 по умолчанию, максимум 50), возвращают `{ items, nextCursor }`. Создание возвращает обращение и HTTP 201; повтор того же `requestId` и содержимого — HTTP 200. Изменённое содержимое с занятым `requestId` возвращает 409.

Лимиты — 5 новых обращений за 10 минут и 20 за 24 часа на аккаунт. Проверка использует PostgreSQL и блокировку только для конкретного пользователя, поэтому лимит и защита от дубликатов работают при нескольких процессах API. HTTP 429 содержит `Retry-After` и `retryAfterSeconds`. Повтор уже сохранённого обращения не расходует лимит. Индексы и постраничная загрузка ограничивают объём чтения; отдельной нагрузочной аттестации этой функции на рабочем сервере не проводилось.

Текст выводится как обычный текст, без HTML. Сервер допускает только известные шаблоны страниц и типы устройств; неизвестные поля игнорируются, управляющие нулевые символы отклоняются. Удаление аккаунта каскадно удаляет его обращения. Отдельного автоматического срока удаления отзывов нет — они входят в резервные копии приложения.

## Проверки

Модульные и интеграционные тесты проверяют границы полей, очистку контекста, повторы, владельца обращения, отсутствие доступа без отдельного права, выдачу и отзыв права без изменения роли, фильтры, пагинацию, гонки отправок и конфликты редактирования. Интеграционные проверки работают на временной PostgreSQL-базе, не на пользовательских данных.

В браузере проверены полный цикл «отзыв → ответ команды → история автора после перезагрузки», сохранение черновика, очистка при смене аккаунта, запрет входящих для обычного пользователя и адаптивная форма на 320/390/1440 px.
