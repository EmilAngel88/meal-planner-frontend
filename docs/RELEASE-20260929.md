## Сборка и исправления процедуры релиза

Образы собраны последовательно на сервере. На время сборки использовался отдельный swap 2 ГБ; после проверки он отключён и удалён. В конце оставалось около 1 ГБ доступной памяти.

При проверке упаковки обнаружено, что архив только с файлами создавал новые родительские каталоги с закрытыми правами. Архив исправлен: каталоги включены с исходными правами, при распаковке используется `--no-same-owner --same-permissions`. Контейнеры продолжают работать от пользователя `node`.

При первом переключении миграции завершились, но обновление каталога остановилось из-за изменившегося пути компиляции seed после добавления импорта из `services`. В `apps/backend/Dockerfile` задан явный `--rootDir apps/backend --outDir apps/backend/dist` и проверяется наличие `dist/prisma/seed.js`. Миграционный образ пересобран; повторный запуск завершился с кодом 0. Это продлило перерыв при переключении; откат данных не потребовался.

Итоговый архив исходников сохранён в папке релиза на сервере. SHA-256: `6ae9385b2a5ab1d7b604cd74a4361913568488ff288f25fb67d7ec80230a6e47`. Документация о завершении релиза добавлена отдельно после проверки.

## Эксплуатация и откат

`TRUST_PROXY=172.18.0.3/32` доверяет текущему адресу контейнера Caddy. Если Caddy пересоздаётся и его адрес меняется, нужно сверить адрес в `evolution_default`, обновить только эту переменную и пересоздать backend. Публичные порты приложения остаются привязанными к `127.0.0.1`.

Предыдущие образы сохранены с тегами `meal-planner-backend:rollback-20260929T062050Z`, `meal-planner-frontend:rollback-20260929T062050Z`, `meal-planner-migrate:rollback-20260929T062050Z`. Не выполнять `docker compose down -v`. Восстановление базы из копии заменяет данные, появившиеся после копирования; это отдельная операция, а не автоматическая часть отката образов. После появления новых целей без демографических полей совместимость старого API нужно проверить перед откатом.

Резервные копии находятся на том же сервере. Внешнее резервирование и полноценный длительный нагрузочный тест целевого сервера этим релизом не настраивались; границы производительности описаны в [CAPACITY.md](CAPACITY.md).
