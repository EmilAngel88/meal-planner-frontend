# Настройка цели: личный ориентир вместо шаблонов

## Что изменилось

Прежний режим «Готовая цель» содержал всего четыре значения: `loss_low: 1800`, `loss_medium: 2000`, `maintain_medium: 2400`, `gain_high: 3000`. Большинство сочетаний не имело значения; параметры человека не влияли на шаблон. Кроме того, одинаковая частота тренировок описывала активность человека с сидячей и физической работой одинаково. Ручной ввод требовал параметры, которые не участвовали в расчёте, а источник сохранённой нормы терялся.

Новый интерфейс предлагает два пути:

- **Рассчитать:** направление → параметры тела → обычный день и тренировки → величина изменения → результат. Для поддержания веса шаг изменения пропускается.
- **Известная норма:** направление → калории, фактический вес и подтверждение возраста 18+ → результат. Никакой дополнительной поправки на направление и никакого округления введённой нормы.

Новая цель не сохраняется в процессе опроса. В итоговом экране есть объяснение цифры и возврат к ответам. После сохранения ответы и способ доступны для повторного редактирования. Старые цели остаются действующими, пока человек сам не сохранит новую. Журнал предлагает явно подставить последнее измерение; автоматически вес профиля и норма не меняются.

## Почему именно эти вопросы

Возраст, пол, рост и вес участвуют в оценке расхода в покое. Фактический вес также используется существующим генератором для белков и жиров. Повседневная подвижность и целенаправленные тренировки спрашиваются отдельно, с предупреждением не учитывать одну и ту же ходьбу дважды. При первом заполнении активность не выбирается за человека. Старую частоту тренировок нельзя достоверно преобразовать в распорядок дня, поэтому при обновлении старой цели эти ответы нужны заново.

Желаемый вес и срок не запрашиваются: используемый расчёт не моделирует достижение конкретного веса к конкретной дате. Диагнозы, лекарства, сон и стресс не собираются: текущая модель не умеет корректно превращать эти данные в поправки. Область применения автоматического расчёта обозначена до ввода параметров. Особые состояния требуют индивидуальной нормы, а не ещё одного универсального коэффициента.

## Метод и его границы

Расход в покое оценивается по Миффлину — Сан Жеору: `10 × вес + 6,25 × рост − 5 × возраст + 5` для мужчин, последний член `−161` для женщин. Неокруглённый результат используется для следующих действий. Источник: [оригинальная работа Mifflin et al., 1990](https://pubmed.ncbi.nlm.nih.gov/2305711/). Формула даёт оценку, а не измерение; исследование взрослых не делает её одинаково точной для всех возрастов и состояний.

Важна активность всего дня. [FAO/WHO/UNU](https://www.fao.org/4/y5686e/y5686e07.htm) рассматривает привычный образ жизни и физическую нагрузку совместно. На этой основе сервис использует **собственную грубую шкалу**, а не валидированный опросник и не точное воспроизведение метода FAO:

| Обычный день | Базовый коэффициент |
| --- | ---: |
| В основном сижу | 1,40 |
| Сижу и двигаюсь | 1,55 |
| Большую часть дня на ногах | 1,70 |
| Физически работаю | 1,90 |

| Целенаправленные занятия с заметным усилием за неделю | Добавка к коэффициенту |
| --- | ---: |
| Нет | 0 |
| Меньше 2 часов | 0,05 |
| От 2 до 4 часов включительно | 0,10 |
| Больше 4 часов | 0,20 |

Коэффициенты — прозрачные продуктовые допущения. Они не учитывают точно интенсивность, состав тела, профессиональный спорт или индивидуальные особенности обмена. Уровень 1,40 не эквивалентен старому 1,20: это новая шкала с другим смыслом, поэтому автоматического переноса старых ответов нет.

От оценки поддержания применяется небольшая поправка: снижение −10% / −15%, набор +5% / +10%, поддержание 0%. По умолчанию выбран меньший шаг. Эти величины — стартовые настройки продукта, а не клиническое назначение и не доказательство определённой скорости изменения веса. Итог автоматического расчёта округляется до 50 ккал; ручное значение сохраняется точно.

Область сервиса — взрослые от 18 лет. Расчёт не предназначен для беременности, грудного вскармливания или лечебной диеты. Автоматическое снижение не предлагается при ИМТ ниже 18,5 — это ограничение инструмента, не диагноз. Расчёт с неположительным расходом в покое либо итогом вне 1 000–10 000 ккал отклоняется, а не заменяется границей диапазона. Новые ручные нормы используют тот же диапазон; старые сохранённые значения не переписываются. Минимум 1 000 — техническое ограничение области применения, **не утверждение, что любая норма выше безопасна или достаточна**. См. ограничения [NIDDK Body Weight Planner](https://www.niddk.nih.gov/bwp) и классификацию ИМТ [NIDDK](https://www.niddk.nih.gov/health-information/weight-management/healthy-eating-physical-activity-for-life/health-tips-for-adults).

Итог предлагается оценивать по тенденции нескольких измерений и самочувствию через 2–4 недели. Это напоминание продукта, не автоматическая калибровка. По одному взвешиванию калории не меняются. Общий принцип наблюдения и пересмотра привычек согласуется с [CDC](https://www.cdc.gov/healthy-weight-growth/losing-weight/index.html).

## Хранение и совместимость

- `POST /calories/goal/preview` валидирует ответы и возвращает оценку без записи.
- `POST /calories/goal` повторно рассчитывает результат на сервере и сохраняет только разрешённые данные. Подставленные клиентом калории/коэффициент/идентификатор пользователя для автоматического режима игнорируются.
- `Profile.goalSetup` хранит `version: 1`, исходные ответы, составляющие результата и дату сохранения. Новая версия анкеты независима от старой формулы `/calculate`.
- Для ручного режима `age`, `gender`, `height`, `activity` равны `null`: фиктивные значения не нужны. При переходе в расчёт отсутствующие параметры запрашиваются явно.
- Новая анкета хранит активность в `goalSetup.input`; старое `activity` равно `null`. Генератор использует вес и калории, поэтому совместимость сохраняется.
- Старые `/calculate`, `/manual`, `/preset` сохранены для совместимости. Запись через них очищает устаревшее `goalSetup`. Старые шаблоны больше не предлагаются в интерфейсе.
- Аддитивная миграция `20260929000000_goal_assessment` не меняет существующие калории или данные меню. Перед применением к локальной базе создана резервная копия.
- Новая цель применяется только к будущим меню. Снимки и цели существующих меню остаются неизменными.

## Проверки

Модульные проверки покрывают формулу, обе части активности, все сочетания выбора, округление, границы, ручной ввод, защиту от подмены результата, восстановление и ветвление анкеты. Интеграционные проверки на временной PostgreSQL проверяют отсутствие записи при предпросмотре, сохранение ответов, изоляцию пользователей, совместимость со старыми маршрутами, генерацию с ручным профилем без демографии и неизменность исторических меню. Проверены сценарии браузера на компьютере и при ширине 390 px: ошибки полей, снижение, поддержание без лишнего шага, отмена, восстановление после перезагрузки и ручная норма без округления.
