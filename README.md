# Рацион · Meal Planner

Личное приложение для рецептов, целей по калориям, меню на шесть дней с одним свободным днём и списка покупок. Интерфейс на русском, данные хранятся в PostgreSQL.

Рабочая версия — этот монорепозиторий. Соседний каталог `../meal-planner-backend` — прежняя отдельная версия API; текущие команды его не используют.

## Первый запуск

Нужны Node.js 24 (или >=22.12), npm >=10 и PostgreSQL. Используйте Node из `.nvmrc`: старый системный npm не поддерживает workspaces.

```sh
nvm use
npm ci
cp apps/backend/.env.example apps/backend/.env
cp apps/frontend/.env.example apps/frontend/.env
```

**Не перезаписывайте существующие `.env`.** В `apps/backend/.env` задайте подключение `DATABASE_URL` к своей базе и случайный `JWT_SECRET`. Секрет можно создать командой `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Файлы `.env` не попадают в Git.

```sh
npm run db:generate
npm run db:migrate
npm run seed
npm run dev
```

Откройте <http://localhost:3000>. API слушает `127.0.0.1:5001`; проверка доступности базы — `GET /health`. Для отдельного запуска: `npm run dev:frontend` и `npm run dev:backend`. Общая команда останавливает оба процесса при выходе или ошибке.

API читает `apps/backend/.env` независимо от папки запуска. Корневой `.env` предназначен для Docker Compose. Настройки адреса и CORS фиксируются до инициализации базы; переменные окружения процесса имеют приоритет. По умолчанию локальный API разрешает frontend на `localhost:3000` и `127.0.0.1:3000`.

`seed` добавляет/обновляет базовый каталог (77 актуальных продуктов, 1 архивная позиция, 38 рецептов, активности), не изменяя одноимённые личные продукты. Повторный запуск не создаёт дубликатов. Новые аккаунты создаются через регистрацию, демонстрационных паролей нет.

## Использование

Готовое [видеоруководство](docs/tutorial/README.md) показывает весь путь от настройки цели до покупок и календаря готовки: 5 минут 49 секунд, 17 глав, русские субтитры.

Обновлённый интерфейс строится вокруг цепочки **цель → неделя → покупки**. Главный экран «Обзор» показывает следующий шаг и блюда выбранной недели. На компьютере используется боковая навигация, на телефоне — нижняя. Подход и структура описаны в [решениях по интерфейсу](docs/UX-REDESIGN.md).

1. Зарегистрируйтесь, в разделе «Моя цель» заполните параметры и сохраните цель. Доступны пошаговый расчёт с учётом повседневной активности и ручной ввод известной нормы.
2. В разделе «Продукты» найдите базовую основу или добавьте свою марку по этикетке. В «Рецептах» используйте библиотеку или создайте своё блюдо: копируйте основу, заменяйте ингредиенты, добавляйте шаги и условия хранения. Выход рецепта задаёт деление состава на порции; «Сколько готовим?» отдельно пересчитывает всю партию. Подробнее: [продукты и приготовление](docs/product-and-recipe-model.md).
3. Укажите дату, распределение питания и рецепты в разделе «Моя неделя» через «Новая неделя». По умолчанию белки и жиры рассчитываются по весу (1,75 и 0,9 г/кг), углеводы — из остатка калорий по [методике 3 × 15](http://3-x-15.ru/). Ручной режим Б/Ж/У использует проценты от 0 до 100, в сумме 100%. Доли приёмов пищи также вводятся в процентах и нормализуются автоматически. API хранит их как доли от 0 до 1.
4. Сохранённые меню доступны из истории и после перезагрузки. Индикатор проверяет отклонение калорий каждого дня в пределах 10%; он не оценивает медицинскую пригодность рациона.
5. Откройте «Покупки». Повторите меню на неделю, 14/28 дней или месяц от выбранной даты. Свободный день оставьте без продуктов или заполните повтором дня меню. Раздел рассчитает целые пачки, весовые покупки с округлением вверх до 50 г/мл, начальные запасы и остатки; покажет вклад каждого блюда. Фасовки подставлены как редактируемые ориентиры, цены вводятся по своему магазину. Закупки распределены по датам, календарь готовки показывает партии, порции и размораживание. Настройки сохраняются в браузере для аккаунта и меню; фактического списания запасов и подключения магазинов нет. Копирование и CSV содержат выбранный поход, TXT — весь график закупок. Подробнее: [Покупки и готовка](docs/shopping.md).

Меню хранит снимок состава и питательности на момент генерации: изменение/удаление исходного рецепта не меняет прежние покупки. Для меню, созданных до миграции снимков, состав восстановлен из доступных на момент обновления ингредиентов. Уже утраченный исторический состав восстановить невозможно.

Расчёт питания ориентирован на взрослых. Формула, ограничения порций и отличие от исходного сайта описаны в [методике генерации](docs/nutrition-method.md). Вес продуктов соответствует явно указанному состоянию. Миллилитры переводятся в граммы по плотности продукта; КБЖУ на 100 мл нормализуются перед расчётом. Внутренний вес ингредиентов хранится в граммах. Пользовательские рецепты без ингредиентов сохраняются как черновики и не участвуют в генерации.

В каждом приёме пищи — одно блюдо и не более одного совместимого дополнения. Учитывается ориентировочный вес готовой еды, включая увеличение крупы при варке. При высокой цели калории распределяются между пятью или шестью приёмами. Генератор сравнивает несколько полных вариантов дня после уточнения порций, стремясь попасть в калории без чрезмерного объёма еды. Отдельного ограничения 65 г для овсянки нет. После подбора уточняются количества отдельных ингредиентов простых базовых блюд; личные рецепты сохраняют пропорции. Откройте «Состав порции», чтобы увидеть точные количества. Число и порядок приёмов пищи можно изменить в настройках распределения. Точное попадание в цель уступает ограничениям порций: если нужного сочетания нет, меню содержит предупреждение и показывает отклонения каждого дня. Старые меню не пересчитываются; для нового алгоритма создайте новое меню. При обновлении существующей установки выполните миграции и `npm run seed`, чтобы добавить новые варианты завтраков и перекусов.

## Монетизация

Добавлены бесплатный и платный тарифы, пробный период, оплата в рублях через ЮKassa и отдельная панель владельца. Цены, лимиты, сроки и варианты оплаты редактируются в интерфейсе, сохраняются в базе и имеют историю изменений. По умолчанию ограничения и продажи выключены. Старые меню и покупки доступны независимо от тарифа. Перед запуском обновления примените миграции и выдайте своему аккаунту отдельный доступ владельца. Пошаговая настройка и подключение магазина — [Монетизация](docs/monetization.md).

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run test:integration
npm run build
# Линтер, типы, модульные тесты и сборка вместе:
npm run check
```

Интеграционные тесты используют настоящие HTTP-запросы и PostgreSQL. Они создают отдельную временную базу `meal_planner_test_*`, применяют все миграции и базовый каталог, затем удаляют только эту тестовую базу. Пользовательская схема `public` не изменяется. По умолчанию берут локальный `DATABASE_URL`; для отдельного сервера явно задайте `TEST_DATABASE_URL`. У пользователя БД должны быть права на создание и удаление тестовых баз.

Итоги комплексной проверки интерфейса и безопасности — [Аудит](docs/PROJECT-AUDIT.md). Браузерные сценарии и предыдущие результаты — `docs/WORKLOG.md`.

Для нагрузочной проверки на отдельном PostgreSQL с правом создавать тестовые базы: `TEST_DATABASE_URL=... npm run test:capacity`. Скрипт создаёт и удаляет только свою временную БД. Измерения, настройки пула и пределы масштабирования описаны в [Многопользовательской работе](docs/CAPACITY.md).

Перед запуском обновлённого API выполните `npm run db:migrate`: миграция `20261001000000_capacity_indexes` добавляет функцию поиска и индексы. Не пропускайте её — поиск продуктов зависит от новой функции.

## Docker

CI/CD в GitHub Actions проверяет код и базу, собирает контейнеры и проверяет запуск приложения. После подключения сервера успешные изменения ветки `master` автоматически развёртываются с резервной копией базы. Настройки, включение и откат описаны в [CI/CD](docs/ci-cd.md).

Для запуска frontend, backend и отдельного PostgreSQL в контейнерах:

```sh
node scripts/init-docker-env.cjs
docker compose up --build
```

Приложение доступно на <http://localhost:8080>, API — на <http://localhost:8081>. Миграции и базовый каталог готовятся автоматически; данные PostgreSQL сохраняются в именованном томе. Скрипт создаёт отдельный корневой `.env` со случайными секретами и не перезаписывает существующие файлы. Подробнее о настройках production, резервном копировании и остановке — [Docker](docs/docker.md).

## Сборка и размещение без Docker

```sh
npm run build
npm --prefix apps/backend start
# В другом терминале:
node apps/frontend/.output/server/index.mjs
```

При размещении за reverse proxy задайте адрес API через `NUXT_PUBLIC_API_BASE` для frontend и список разрешённых адресов через `CORS_ORIGINS` для API. Для доступа к API извне контейнера задайте `HOST=0.0.0.0` только в конфигурации размещения. Нужны HTTPS, постоянная база, её резервное копирование и собственный секрет JWT. Токен хранится локально в браузере, живёт семь дней; сервер проверяет права на каждом запросе. При работе через прокси задайте только его адреса/CIDR в `TRUST_PROXY`, закройте прямой внешний доступ к API и настройте внешние ограничения запросов. По умолчанию доверие заголовкам IP отключено. Production не запускается с коротким JWT-секретом или известной заглушкой.

## Архитектура

- `apps/frontend` — Nuxt 3, Vue, Pinia, Vuetify; клиентское приложение с защищённой навигацией. Приватные данные загружаются через API; серверной индексации личных страниц нет.
- `apps/backend` — Express 5, Prisma, PostgreSQL; схемы входных данных в `utils/validation.ts`, алгоритм подбора в `services/generator.ts`, покупки в `services/shopping.ts`.
- `apps/backend/prisma` — схема, добавочные миграции, повторяемое заполнение каталога.
- `apps/backend/tests` — проверки бизнес-правил и интеграции с изолированной БД.
- `apps/frontend/utils/purchases.ts` — независимый расчёт покупок и экспорт; `apps/frontend/tests` — его модульные проверки (входят в `npm test`).
- `packages/shared` — сохранённое место для будущих общих контрактов; пока не используется.
- `../Meal Planner Design System` — исходные материалы оформления; приложение использует уже перенесённые стили.

Миграции применяются командой `migrate deploy`; не используйте `migrate reset` на рабочей базе. Перед обновлением можно сделать резервную копию: `node scripts/backup-db.cjs` (нужен `pg_dump` в PATH). Копии в `.backups/` исключены из Git.

Зависимость `deepmerge-ts` в инструменте Prisma закреплена на исправленной версии 8.0.0 через `overrides`. Проект не использует изменённое объединение Map; генерация клиента, миграции и тесты проверяются с этой версией. [Описание исправления](https://github.com/RebeccaStevens/deepmerge-ts/releases/tag/v8.0.0).

Rolldown закреплён в корневых инструментах сборки: при косвенной peer-зависимости npm терял платформенные пакеты и чистая установка не могла запустить сборщик Nuxt. Проверяйте изменения lockfile через `npm ci` и `npm run check`.
