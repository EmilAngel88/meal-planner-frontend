# Серверное развёртывание

## Обновления через CI/CD — 30 сентября 2026

Проект опубликован в [GitHub](https://github.com/EmilAngel88/meal-planner-frontend). Обновления выполняются через окружение `production` из ветки `master`. Параметры подключения задаются в защищённых настройках GitHub.

Обновления запускаются через [Actions → CI / CD](https://github.com/EmilAngel88/meal-planner-frontend/actions/workflows/ci-cd.yml), после тестов, сборки и проверки контейнеров. Текущий результат и история доступны там же. Готовые образы загружаются из GitHub Container Registry; сборка на сервере больше не нужна. Перед миграциями создаётся проверенная копия базы. Успешный выпуск сохраняет свою конфигурацию и закреплённые версии образов.

**Для последующих обновлений используйте CI/CD.** Исходники первоначальной установки не синхронизируются с каждым выпуском: запуск старой команды `docker compose up --build` из того каталога может вернуть прежний код. Серверные настройки и существующий том базы сохраняются. Настройки и действия при ошибке описаны в [CI/CD](ci-cd.md).

## Конфигурация

Серверный `.env` имеет права `0600` и содержит независимо сгенерированные секреты. Не копировать его в Git или клиентскую сборку. Дополнительно к обычным переменным Docker он содержит:

```dotenv
COMPOSE_FILE=docker-compose.yml:docker/compose.edge.yml
PROXY_NETWORK=evolution_default
NUXT_PUBLIC_API_BASE=https://menu.109-172-39-39.sslip.io/api
CORS_ORIGINS=https://menu.109-172-39-39.sslip.io
```

Наложение `docker/compose.edge.yml` подключает frontend/backend к существующей сети прокси, с именами `meal-planner-web` и `meal-planner-api`. PostgreSQL остаётся только во внутренней сети приложения. Порты 8080/8081 опубликованы на `127.0.0.1`.

В существующий `/opt/evolution/Caddyfile` добавлен отдельный блок сайта по образцу `docker/Caddyfile.example`. API доступен под `/api/`, прокси удаляет этот префикс перед передачей backend. HTTPS-сертификат получен автоматически, его обновлением управляет существующий Caddy. Прокси перечитал настройки без перезапуска игры. Исходные настройки сохранены в `/var/backups/meal-planner/initial-proxy/`.

Временный адрес использует внешний DNS-сервис [sslip.io](https://sslip.io/). Для своего домена нужно направить A-запись на сервер, заменить имя в Caddyfile, `NUXT_PUBLIC_API_BASE` и `CORS_ORIGINS`, затем пересоздать контейнеры и перечитать конфигурацию Caddy. [Документация маршрутизации API в Caddy](https://caddyserver.com/docs/caddyfile/directives/handle_path).

## Обновление и резервная копия

На сервере из `/opt/meal-planner`:

```sh
umask 077
docker compose exec -T postgres pg_dump -U meal_planner -d meal_planner -Fc > /var/backups/meal-planner/database/before-update.dump
# Обновить исходники, сохранив серверный .env.
COMPOSE_PARALLEL_LIMIT=1 docker compose --ansi never up --build -d --wait --wait-timeout 180
docker compose ps --all
```

Первичная копия базы: `/var/backups/meal-planner/database/initial-20260928.dump` (дата UTC). Формат проверен через `pg_restore --list`. Копия хранится на том же сервере; автоматические и внешние резервные копии пока не настроены. Не удалять том `meal-planner_postgres_data` при обновлении. Инструкция восстановления — в `docs/docker.md`.

Сервер имеет 2 ГБ памяти. Сборка выполнялась последовательно с временным swap 2 ГБ; после сборки swap отключён, временный файл удалён. Для следующих сборок при недостатке памяти стоит собирать образы вне рабочего сервера либо снова временно выделить swap. Работающим приложениям после запуска оставалось около 1 ГБ доступной памяти.

## Доступ с текущего Mac

Обнаружена проблема маршрута через VPN: сервер принимал TCP-соединение, но SSH/HTTPS зависали. При явном выборе Wi-Fi (`en0`) связь работает:

```sh
ssh -B en0 root@109.172.39.39
curl --interface en0 https://menu.109-172-39-39.sslip.io/api/health
```

Настройки VPN и системные маршруты не менялись. Если сайт не открывается в браузере при включённом VPN, нужно исключить адрес сервера/сайта из VPN-маршрута либо проверить с другого подключения. Полный браузерный сценарий на этом Mac при текущем VPN не проверен; публичный API-сценарий проверен с сервера.
